# Sector Trooper — saber variant

A separate melee equipment study derived from `../head/sector-trooper-head.blend`.
The canonical rifle character and game asset are unchanged.

- `sector-trooper-saber.blend`: editable character, original rig and source actions,
  plus six saber actions. `Saber_Run_Swing` is selected, frames 1–18 at 24 fps.
- `sector-trooper-saber.glb`: body, hand-attached saber and six clips:
  idle, run, standing forehand/backhand and running forehand/backhand. glTF +Y up, +Z facing; original character origin retained.
- `saber-hero.png`, `saber-front.png`, `saber-side.png`: rendered inspection views.
- `build_saber.py`: reproducible variant construction, export and renders. Run in
  background Blender with the canonical head blend as input. Never saves over it.
- `validate_saber.py`: independent GLB import and eight samples per clip against
  the temporary reference generated by the animator. Run in background Blender.
- `asset-stats.json`, `validation.json`: construction and export validation results.

The weapon has an ivory emitter and pommel, graphite grip, alloy grip rings,
cyan ignition ring and a 0.946 m cyan blade with bright facets. It attaches to the
existing `weapon` socket below `hand.R`. No new rig bones or character topology
changes are required. Both gloves retain their original rigid hand binding.
The right wrist turns outward slightly for a clearer silhouette, and the left
arm drops into a relaxed guard. The idle breathes subtly without grip drift.

All 71 original body meshes and 17 source actions remain in the blend. The rifle
objects are removed only from this variant. The GLB contains only the six saber
clips; reference rifle/unarmed actions are retained in Blender for authoring.

## Animation

| Clip | Duration | Playback frames at 24 fps | Behavior |
| --- | --- | --- | --- |
| Saber_Idle | 3 s | 1–72; matching end 73 | Relaxed breathing ready pose |
| Saber_Run | 0.75 s | 1–18; matching end 19 | Forward run, right-hand saber guard, left arm pumps |
| Saber_Swing | 0.9167 s | 1–23 | Forehand from character-right across to character-left |
| Saber_Backhand | 0.9167 s | 1–23 | Backhand from character-left across to character-right |
| Saber_Run_Swing | 0.75 s | 1–18; matching end 19 | Forehand during an uninterrupted run stride |
| Saber_Run_Backhand | 0.75 s | 1–18; matching end 19 | Backhand during an uninterrupted run stride |

The character holds **one saber** throughout. Standing attacks start and end in the
same idle pose and use wind-up, cut, follow-through and recovery. Their principal
strike is frame 9 (0.3333 s), with a suggested active interval of 0.25–0.4583 s.
These are integration markers, not implemented damage events. Both clips can be
selected independently. Dual wielding is reserved for the later both-sides upgrade.
Saber_Death adds a three-second, non-looping forward fall onto the stomach with a sideways head turn.

Running attacks preserve the run’s complete lower-body transforms and actor pace.
They retain the standing slash’s wind-up and impact timing, with a quicker recovery
to finish in one run cycle. The free arm tucks during the attack and resumes its
pump afterwards. Both endpoint poses match the ordinary run at that gait phase.
When integrating attacks triggered midstride, retain the independent run clock and
lower-body tracks; layer/blend the upper-body attack instead of restarting the legs.
The Blender clips demonstrate the complete combined motion at a common gait phase.

All clips keep the root fixed. Run preserves the source Run's lower-body IK and
foot transforms exactly: 1.32 m stride at 1.76 m/s. Apply character scale and
playback rate to that speed when integrating movement. The sword arm uses a
restrained pump while the unarmed left arm retains the original running motion.

- `animate_saber.py`: run in background Blender against the backup at
  `revisions/pre-animation/sector-trooper-saber.blend`. Saves the updated canonical
  saber blend, then exports four clips to GLB at 96 Hz to preserve quarter-frame
  keys and baked IK. Retiming is not saved into the editable blend.
- `animate_running_attacks.py`: run against `revisions/pre-running-attacks/sector-trooper-saber.blend`
  to add the two running attacks, save the complete six-clip blend/GLB and refresh
  animation/export reference data.
- `validate_saber.py`: independently imports that GLB and compares all exported clips
  to evaluated source geometry at eight samples each.
- `check_clearance.py`: samples the saved Blender clips at quarter-frame intervals
  and ray-checks the blade centreline against the evaluated character meshes.
- `render_animation.py`: renders run, forehand and backhand movies and pose stills.
- `saber-run.mp4`, `saber-swing.mp4`, `saber-backhand.mp4`: four repeated cycles each.
- `animation-stats.json`, `validation.json`, `clearance-check.json`: latest checks.

The animated GLB is integrated in the core-survivors worktree (see below).
The original build script recreates the initial idle-only study, so run the animator
followed by the running-attack authoring step and checks after rebuilding it
to restore the complete animation set.

## Survivor game integration

The `core-survivors` worktree now uses this six-clip, one-saber asset as its player.
The game splits upper/lower tracks to retain gait phase through attacks and pauses,
scales swing speed to weapon cooldown, and applies damage at the frame-12 side cut.
A cyan crescent marks the shared half-ellipse damage envelope, expanding with range
and Area upgrades. Dual wielding remains deferred. Player death now uses Saber_Death, with a spiral overhead zoom and a one-second hold before results.

`animate_death.py` authors the collapse from the idle rig pose, solving legs and
arms and retaining the six previous clips. The pre-death live Blender state is
preserved under `revisions/pre-death/live-before-death.blend`.

The prone revision is generated by animate_death.py; the previous kneeling version
is preserved under revisions/pre-prone-death/. Full evaluated geometry is kept
above the source floor throughout the fall.

Staged death: knees land at 0.85 s, the pose holds until 1.3 s, and the trooper
falls forward to impact at 2.35 s, settling by 3 s. Death disables foot IK while
other actions retain it. `merge_death_export.py` preserves the approved geometry
and six combat animation buffers exactly, importing only the new death channels.
The previous prone clip is backed up under `revisions/pre-staged-death/`.
